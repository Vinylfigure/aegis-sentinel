Aegis Workbench · program design as pipeline

Scope determines the program; the program determines the datasets; the datasets determine what the agents do. Each stage feeds the next — the Overlord console at the end is generated, not authored.

Products carrying a commitment, the data classes they hold, and the system registry. Only in-scope systems become available for control mapping downstream — an unknown system blocks nothing here but taints every control mapped to it.

Products & data
System registry

The control library, seeded from the Aegis testing matrix. Classify each control's nature (configurable · automated-detective · manual) and function (preventative · detective), flag compensating controls, and map the in-scope systems it operates over. The posture gauges on the right respond live.

The dataset registry — derived from control↔system mappings, deduplicated. A dataset shared by many controls is the test-once-apply-many win; set its artifact type, retrieval channel, and C&A method once and every control that rides it inherits.

Overlord console. One deterministic collector mission per unique dataset — target, retrieval surface, verdict attributes, cadence, C&A, evidence destination. The LLM lane sits above the verdict path: triage, narrative, mapping — never verdicts. This is the scope of what each agent is allowed to do, generated from everything upstream.
